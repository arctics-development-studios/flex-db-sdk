Overview

FlexDB is a key-value Database-as-an-API with automatic storage tiering. All requests and responses use JSON. Every response body (success or error) carries a top-level v field containing the server's semver version string and a top-level ok boolean.

Base URL

The server does not mandate a particular hostname. Deploy it wherever you like and use that host as the base. All paths in this document are relative to that base.

Response Envelope

Every response is wrapped in a consistent envelope:

Success

{
  "v": "2.5.0",
  "ok": true,
  "data": { ... }
}

Error

{
  "v": "2.5.0",
  "ok": false,
  "error": {
    "code": "ERR_NOT_FOUND",
    "message": "the requested resource was not found"
  }
}

Content-Type

All requests with a body must send Content-Type: application/json. All responses are Content-Type: application/json.

Authentication

There are two independent authentication schemes. Both use the Authorization HTTP header with a Bearer token.

Authorization: Bearer <token>

Master Token (Admin)

A static secret configured on the server via the MASTER_TOKEN environment variable. Used exclusively for admin endpoints under /admin/db. Validated with a constant-time comparison to prevent timing attacks. There is only one master token per server deployment.

RS256 JWT (Data)

Signed JSON Web Tokens used for all data endpoints under /v2/. Tokens are issued by the server via the Create API Key endpoint and signed with a 2048-bit RSA private key (RS256 algorithm). The server validates the signature using the corresponding public key.

JWT Claims

ClaimTypeDescription
issstringIssuer, set from JWT_ISSUER env var
iatnumberIssued-at unix timestamp (seconds)
expnumberExpiry unix timestamp (seconds). Absent if the token was created with expiry_secs: null (non-expiring token)
jtistringUnique token ID (nanoid-21). Used for revocation lookups.
db_idstringThe database this token is scoped to
permsnumberPermission bitmask (see below)

Permission Bits

ValueNameGrants access to
1READGET object, LIST, SEARCH, BULK GET
2WRITEPUT object, DELETE object, BULK SET, BULK CREATE, BULK DELETE
3ALLREAD + WRITE (bits 1 and 2 combined)

Permission checks use bitwise AND: a token with perms=3 passes both READ and WRITE checks.

Token Revocation

Tokens are stored in DynamoDB and cached in Redis by jti. A revoked token's jti entry is removed from both stores. The server rejects any token whose jti is not found in the store, even if the JWT signature is valid. Deleting a database automatically revokes all of its tokens.

Rate Limiting

Rate limits are enforced per database on all data endpoints. There are two independent limits:

LimitDescriptionResets
RPSMaximum requests per second for this databaseEvery second
MonthlyMaximum total requests per calendar monthStart of each calendar month

When a limit is exceeded the server returns 429 Too Many Requests with the appropriate error code (ERR_RATE_LIMIT_SECOND or ERR_RATE_LIMIT_MONTH).

Response Headers

Every data endpoint response (success or rate-limit error) includes these headers:

HeaderTypeDescription
x-ratelimit-rps-remainingintegerRequests remaining in the current second window. Always present when an RPS limit is configured.
x-ratelimit-month-remainingintegerRequests remaining in the current calendar month. Only present when a monthly limit is configured (limit > 0).

Limits are based on the database's plan type. A limit of 0 means unlimited for that dimension.

Errors

All errors use the envelope described in Overview. The error.code field is a stable string constant that SDK authors should match against programmatically. The error.message field is human-readable and may change between server versions.

Error Codes

CodeHTTP StatusDescription
ERR_MISSING_AUTH401No Authorization header was provided
ERR_UNAUTHORIZED401Token is invalid, expired, revoked, or the master token does not match
ERR_PERMISSION_DENIED403The JWT does not have the required permission bit for this operation
ERR_FORBIDDEN403Access denied for another reason (e.g., IP whitelist)
ERR_NOT_FOUND404The requested object, database, or resource does not exist
ERR_CONFLICT409Key already exists (returned per-item in bulk create, not as top-level error)
ERR_REQUEST_TOO_LARGE413The serialized object size exceeds the server's configured maximum cold-storage size
ERR_BULK_TOO_LARGE413The bulk operation contains more items than the server's configured bulk limit
ERR_UNPROCESSABLE_ENTITY422The request body could not be parsed as valid JSON
ERR_RATE_LIMIT_SECOND429Per-second RPS limit exceeded for this database
ERR_RATE_LIMIT_MONTH429Monthly request quota exceeded for this database
ERR_MISSING_FILTER400Search request was sent without a non-empty filters array
ERR_INVALID_REQUEST400A required parameter is missing or has an invalid value
ERR_STORE_FAILED500A storage write operation failed internally
ERR_DELETE_FAILED500A storage delete operation failed internally
ERR_INTERNAL500Unexpected internal server error

Status

GET /

Returns server liveness and version. Requires no authentication. Use this as a health check endpoint.

Request

No parameters, no body.

Response — 200 OK

{
  "v": "2.5.0",
  "ok": true,
  "data": {
    "status": "ok",
    "version": "2.5.0"
  }
}

Admin Endpoints

All admin endpoints require a Master Token in the Authorization: Bearer header. The token is validated with a constant-time comparison. Any mismatch returns 401 ERR_UNAUTHORIZED. All admin endpoints can return the following errors in addition to those listed per-endpoint:

CodeHTTP StatusCondition
ERR_MISSING_AUTH401No Authorization header
ERR_UNAUTHORIZED401Token does not match MASTER_TOKEN

DELETE /admin/db/{id} — Delete Database

Permanently deletes the database, revokes all of its API keys, and wipes all stored objects across every storage tier. This operation is irreversible.

Path Parameters

ParameterTypeDescription
idstringDatabase ID

Request Body

None.

Response — 200 OK

{
  "v": "2.5.0",
  "ok": true,
  "data": {}
}

Side Effects

  • All tokens associated with this database are deleted from DynamoDB and Redis (revoked)
  • The database context cache in Redis is invalidated
  • All object data across L1, L2, KV, and Cold tiers for this database is purged

Additional Errors

CodeHTTP StatusCondition
ERR_NOT_FOUND404No database with this ID exists
ERR_INTERNAL500Storage failure during deletion

Data Endpoints

All data endpoints require a valid RS256 JWT in the Authorization: Bearer header. The middleware chain applied to every data request is:

  1. JWT validation — verifies signature, optional expiry, and jti presence in the token store
  2. DB context load — loads the database limits from Redis cache (falls back to DynamoDB)
  3. Rate limit enforcement — checks RPS and monthly quota; rejects with 429 if exceeded
  4. Egress tracking — records response byte count asynchronously after the response is sent

All data endpoints can return these errors in addition to those listed per-endpoint:

CodeHTTP StatusCondition
ERR_MISSING_AUTH401No Authorization header
ERR_UNAUTHORIZED401Invalid JWT signature, expired token, or revoked jti
ERR_PERMISSION_DENIED403Token lacks the required permission bit
ERR_RATE_LIMIT_SECOND429RPS limit exceeded
ERR_RATE_LIMIT_MONTH429Monthly quota exceeded
ERR_INTERNAL500Internal server error

GET /v2/o/{ns}/{key} — Get Object

Retrieves a single object by namespace and key. The server checks storage tiers in order (L1 → L2 → DynamoDB → S3) and populates hotter tiers on a miss. A background task increments the object's access counter and may promote or demote it between tiers.

Required Permission

READ (bit 1)

Path Parameters

ParameterTypeDescription
nsstringNamespace — a logical grouping of keys within the database
keystringObject key within the namespace

Request Body

None.

Response — 200 OK

{
  "v": "2.5.0",
  "ok": true,
  "data": {
    "key": "user:42",
    "data": { "name": "Alice", "score": 9001 },
    "meta": {
      "warm": true,
      "size": 38,
      "updated_at": 1747440000,
      "sp": { "score": 9001, "tag": "admin" }
    }
  }
}

Response Fields

FieldTypeDescription
data.keystringThe object's key as stored
data.dataany JSONThe stored value — any valid JSON (object, array, string, number, boolean, null)
data.meta.warmbooleantrue if stored in DynamoDB (warm tier), false if in S3 (cold tier)
data.meta.sizenumberSerialized size in bytes
data.meta.updated_atnumberUnix timestamp (seconds) of last write
data.meta.spobjectUser-supplied search parameters (see PUT Object)

Additional Errors

CodeHTTP StatusCondition
ERR_NOT_FOUND404No object with this namespace+key exists in this database

PUT /v2/o/{ns}/{key} — Put Object

Creates or replaces an object. If the key does not exist, returns 201 Created. If the key already exists, replaces it and returns 200 OK.

The server determines the storage tier automatically based on the serialized size of the data field:

  • Size ≤ KV_MAX_SIZE → DynamoDB (warm tier)
  • Size > KV_MAX_SIZE → S3 (cold tier)

The server invalidates L1 and L2 caches before writing, then populates both after the write completes.

Required Permission

WRITE (bit 2)

Path Parameters

ParameterTypeDescription
nsstringNamespace
keystringObject key

Request Body

FieldTypeRequiredDescription
dataany JSONYesThe value to store. May be any valid JSON value.
spobjectNoSearch parameters. A flat object of string → scalar pairs used for filtered queries. Field names must be alphanumeric plus underscore, max 64 chars. Values must be JSON scalars (string, number, boolean). Defaults to {}.
 
{
  "data": { "name": "Alice", "score": 9001 },
  "sp": { "score": 9001, "tag": "admin" }
}

Response — 201 Created (new key) or 200 OK (existing key)

{
  "v": "2.5.0",
  "ok": true,
  "data": {
    "key": "user:42"
  }
}

Additional Errors

CodeHTTP StatusCondition
ERR_REQUEST_TOO_LARGE413Serialized data exceeds COLD_MAX_SIZE server limit
ERR_UNPROCESSABLE_ENTITY422Request body is not valid JSON
ERR_STORE_FAILED500Storage write failed

GET /v2/list/{ns} — List Objects

Returns a paginated list of all keys in a namespace. Optionally hydrates each key with its full stored value.

Required Permission

READ (bit 1)

Path Parameters

ParameterTypeDescription
nsstringNamespace to list

Query Parameters

ParameterTypeDefaultDescription
limitnumber100Maximum items to return. Clamped to [1, 1000].
cursorstring—Opaque pagination cursor from a previous response. Omit for the first page.
fullbooleanfalseWhen true, returns full objects with data and metadata. When false, returns only key strings.

Request Body

None.

Response — 200 OK (keys only, full=false)

{
  "v": "2.5.0",
  "ok": true,
  "data": {
    "keys": ["user:1", "user:2", "user:42"],
    "cursor": "eyJsYXN0S2V5IjoidXNlcjo0MiJ9"
  }
}

Response — 200 OK (hydrated, full=true)

{
  "v": "2.5.0",
  "ok": true,
  "data": {
    "items": [
      {
        "key": "user:1",
        "data": { "name": "Bob", "score": 42 },
        "meta": { "warm": true, "size": 27, "updated_at": 1747440000, "sp": {} }
      }
    ],
    "cursor": null
  }
}

Pagination

When cursor in the response is null, there are no more pages. Pass the cursor value as the cursor query parameter to retrieve the next page. Cursors are opaque — do not parse or construct them manually.

Types

This section defines the canonical shapes for complex objects referenced throughout this document.

DbRecord

Represents a database and its current state. Returned by Create, Get, and Update database endpoints.

{
  "id": "string — nanoid-21 unique identifier",
  "name": "string — human-readable name",
  "db_type": "string — plan tier: dev | start | pro | ent | arch",
  "region": "string — AWS region where data is stored",
  "created_at": "number — unix timestamp (seconds) of creation",
  "limits": {
    "rps": "number — max requests per second (0 = unlimited)",
    "month": "number — max requests per calendar month (0 = unlimited)",
    "storage_gb": "number — max storage in gigabytes",
    "egress_gb": "number — max egress in gigabytes per month"
  },
  "usage": {
    "req_this_month": "number — requests made in the current calendar month",
    "storage_bytes": "number — current storage used in bytes",
    "egress_bytes": "number — egress used in the current month in bytes"
  },
  "usage_history": [
    {
      "month": "string — YYYY-MM",
      "usage": {
        "req": "number",
        "storage_bytes": "number",
        "egress_bytes": "number"
      }
    }
  ],
  "overage": {
    "req": "number — requests over the monthly limit",
    "storage_bytes": "number — bytes over the storage limit",
    "egress_bytes": "number — bytes over the egress limit"
  }
}

PlanLimits

The set of hard limits assigned to a database based on its db_type (plan). These are configured server-side and are not modifiable per-database.

{
  "rps": "number — requests per second cap",
  "month": "number — monthly request cap",
  "storage_gb": "number — storage cap in GB",
  "egress_gb": "number — egress cap in GB per month"
}

ObjectMeta

Metadata attached to every stored object. Returned alongside the object's data in GET and full-hydration list/search responses.

{
  "warm": "boolean — true if object resides in DynamoDB, false if in S3",
  "size": "number — serialized byte size of the stored value",
  "updated_at": "number — unix timestamp (seconds) of the last write",
  "sp": "object — user-supplied search parameters: { [field: string]: string | number | boolean }"
}

TokenRecord

Metadata for an issued API key. Returned by the List API Keys endpoint. The JWT string itself is never returned again after issuance.

{
  "jti": "string — unique token ID (nanoid-21), matches the jti JWT claim",
  "db_id": "string — database this token is scoped to",
  "perms": "number — permission bitmask (1=READ, 2=WRITE, 3=ALL)"
}

SearchFilter

A single filter condition used in the Search endpoint. Multiple filters are ANDed together.

{
  "field": "string — sp field name to filter on",
  "op": "string — eq | neq | gt | gte | lt | lte | sw | ex",
  "value": "string | number | boolean — scalar value to compare against"
}

BulkResultItem (Set / Create)

Per-item result returned in the data array of Bulk Set and Bulk Create responses.

{
  "key": "string",
  "ok": "boolean",
  "error": "string — present only in Bulk Set when ok=false",
  "conflict": "boolean — present only in Bulk Create; true if key already existed"
}

BulkGetItem

Per-item result returned in the data.items array of Bulk Get responses.

{
  "key": "string",
  "data": "any JSON | null — null if the key does not exist"
}

Storage Tiers (Informational)

The server transparently manages four storage tiers. SDK authors do not control tier assignment directly — it is automatic based on object size and access frequency.

TierTechnologyWhen Used
L1 (in-process)Moka (in-memory)Hot objects, zero network latency, process lifetime
L2 (cache)Valkey / RedisWarm objects, shared across Lambda instances
KV (warm)DynamoDBObjects at or below KV_MAX_SIZE
ColdS3Objects above KV_MAX_SIZE
